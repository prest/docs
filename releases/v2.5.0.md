# v2.5.0

Released: October 7, 2026

[GitHub tag](https://github.com/prest/prest/releases/tag/v2.5.0) · [Compare v2.4.2...v2.5.0](https://github.com/prest/prest/compare/v2.4.2...v2.5.0)

**v2.5.0** adds a **MySQL 8** dialect adapter ([#1048](https://github.com/prest/prest/pull/1048)), fixes restricted JOINs so joined columns follow table access control ([#1032](https://github.com/prest/prest/pull/1032), [#1033](https://github.com/prest/prest/pull/1033)), and fixes middleware plugin builds ([#1039](https://github.com/prest/prest/pull/1039)). Go and Studio dependency bumps ship in the same tag ([#1055](https://github.com/prest/prest/pull/1055)).

- **Docker:** `prest/prest:v2.5.0`
- **Go install:** `go install github.com/prest/prest/v2/cmd/prestd@v2.5.0`

Upgrading from [v2.4.2](v2.4.2.md) is a drop-in pin change unless you turn on MySQL. PostgreSQL stays the default engine.

## Highlights

### MySQL 8 adapter ([#1048](https://github.com/prest/prest/pull/1048))

pREST selects MySQL only when you set `engine = "mysql"` on the root config or a `[[databases]]` entry. An empty `engine` stays PostgreSQL, including Timescale detection. Connection URLs are not probed to guess the engine.

`mysql://` is applied only when `engine` is `mysql`. The port defaults to **3306** when unset. Postgres defaults (user `postgres`, database `prest`, port 5432) are not copied. A missing user or database fails startup.

Environment variables: `PREST_DB_*` is read first, then the legacy `PREST_PG_*` names (and `PREST_AUTH_SCHEMA`).

TLS modes are `disable`, `require`, and `skip-verify`. Setting a client cert, key, or root certificate **fails startup** — custom TLS config is not in this release.

Routes stay `/{database}/{schema}/{table}`:

- `{database}` selects the connection pool (the alias, or the configured database on a single connection).
- `{schema}` is the MySQL database. MySQL treats database and schema as the same thing.
- System schemas `mysql`, `information_schema`, `performance_schema`, and `sys` are hidden from listings. `/databases` and `/schemas` both list user databases.

The floor is **MySQL 8.0.19+** (the upsert row alias). CI runs `mysql:8.0`, `mysql:8.4`, and `mysql:latest`. **MariaDB is out of scope.** TiDB and Aurora MySQL are not certified on this adapter.

Writes do not use SQL `RETURNING`. An insert runs, then `SELECT *` in the same transaction. `AUTO_INCREMENT` uses `LastInsertId()`. `UPDATE` and `DELETE` without `_returning` return `{"rows_affected": n}`. With `_returning`, that suffix is stripped and not sent to MySQL: update selects the post-image, delete selects the pre-image then deletes, both in one `REPEATABLE READ` transaction.

`Prest-Batch-Method: copy` is a transactional multi-row `INSERT`, not `LOAD DATA`.

These operators error on MySQL: `$all`, ltree, `$tsquery`, `vecdist`, and `FULL` join. `$ilike` becomes `LIKE` (the column collation decides case; pREST does not inject `LOWER()`). A JSON filter `col:jsonb` with `field->>attr` maps to `` `col`->>'$.attr' ``.

A missing table (MySQL error 1146) returns **404**, the same as a missing Postgres relation. Health responses name the active engine. `HAVING` filter values are bound on both engines.

**MCP is not part of this adapter.** `/_mcp` stays on the PostgreSQL family. That limit is **v2.5.0 only** and is lifted in [v2.5.1](v2.5.1.md). See [MySQL](../databases/mysql.md).

### JOIN access control ([#1032](https://github.com/prest/prest/pull/1032), [#1033](https://github.com/prest/prest/pull/1033))

Fixes [#364](https://github.com/prest/prest/issues/364) on the **PostgreSQL** adapter. With `restrict=true`, the SELECT list used to come only from the main table, so joined columns were dropped or could leak.

- A joined table adds only columns permitted for that operation and user, qualified with the joined table name. No read permission means no columns from that table.
- Main-table columns are qualified when a join is present, so names do not become ambiguous.
- `_select` accepts qualified fields and a validated `table.*`.

[#1033](https://github.com/prest/prest/pull/1033) also rejects duplicate and self-join targets (including schema-qualified names), rejects a malformed join before a partial result, and keeps multiple `_join` parameters in order.

### Middleware plugins ([#1039](https://github.com/prest/prest/pull/1039))

Fixes [#948](https://github.com/prest/prest/issues/948). The Docker image includes Go module files and the vendor directory so a plugin build shares the server’s module identity. `go-build.sh` builds `.so` middleware with vendor-aware flags. The loader accepts a factory and a direct handler. A missing plugin falls back to no-op middleware instead of failing the request path.

See [Middleware Plugin](../plugins/middleware-plugin.md).

## Upgrading from v2.4.2

1. Deploy `prest/prest:v2.5.0`, the matching binary, or `go install github.com/prest/prest/v2/cmd/prestd@v2.5.0`.
2. Leave `engine` unset to stay on PostgreSQL. Set `engine = "mysql"` only for a MySQL 8.0.19+ server. Do not point this adapter at MariaDB.
3. If you skipped [v2.4.2](v2.4.2.md), check `jwt.key` length first. A short HMAC key does not stop startup — it disables `/auth`. See [v2.4.2 — Upgrading](v2.4.2.md#upgrading-from-v241).
